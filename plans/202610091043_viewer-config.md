# Viewer config and the NaoViewer object

**Status:** Done

Implements [specs/config.md](../specs/config.md) (`NaoViewerConfig` and its loaders, example files) and the reworked public API of [specs/api.md](../specs/api.md): a `NaoViewer` built from a config, with `launch()` as a method, replacing the `launch()` function and the `Viewer` handle. The viewer process, the protocol and the window are unchanged apart from reading the config. It leaves out `nao-viewer view --config` (cli.md has its own plan).

## Scope

- `src/nao_viewer/config.py` — new: `NaoViewerConfig`, `NaoqiSettings`, `WorldSettings`, `ConfigError`, the loader trio, `to_dict`
- `src/nao_viewer/client.py` — `NaoViewer` replaces `launch()` + `Viewer`; same process handling underneath
- `src/nao_viewer/viewer_process.py` — reads its argument with `NaoViewerConfig.from_dict`
- `src/nao_viewer/__init__.py` — the new export list
- `examples/configs/mirror.json`, `examples/configs/sim-table.json` — new
- `tests/test_config.py` — new
- `tests/test_client.py`, `tests/fake_viewer_process.py`, `tests/test_viewer_process.py`, `tests-e2e/test_viewer_live.py` — moved to `NaoViewer` and the config format
- `AGENTS.md` — project map: `config.py`, `client.py`'s role, the `examples/` root directory
- `specs/config.md`, `specs/api.md`, `specs/_index.md`, this plan — statuses

## Steps

1. **`config.py`**, after nao-bridge's `config.py`, trimmed to what nao-viewer needs:
   - `ConfigError(ValueError)` with `key` and `detail`; `str()` is `"<key> <detail>"`.
   - Value readers `as_bool`, `as_number` (rejects booleans, requires finite), `as_str`, `as_choice(...)`; `parse_block(factory, data, path, **readers)` rejecting non-objects and unknown keys, passing only present keys so dataclass defaults apply, and prefixing a block's own `__post_init__` errors with its path.
   - `JsonConfig` base: `parse` (per class), `from_dict`, `from_json`, `from_json_file` (errors name the file).
   - Frozen dataclasses `NaoqiSettings`, `WorldSettings`, `NaoViewerConfig` with the spec's defaults; range checks in `__post_init__` so direct construction validates too.
   - Scenes: the bundled names are the `*.xml` stems in `src/nao_viewer/scenes/` (listed with `importlib.resources`, no MuJoCo); `from_json_file` resolves a relative `.xml` scene against the file's directory.
   - `to_dict()` on each class: every field, nested blocks as dicts.
2. **`client.py`**:
   - `NaoViewer(config=None)` keeps the config; `from_dict` / `from_json` / `from_json_file` classmethods; `config` property.
   - `launch()`: today's `launch()` function body, reading the config (`mode`, `launch_timeout_s`) and passing `json.dumps(config.to_dict())` to the viewer process; `RuntimeError` if already running; after an exit, a new launch replaces the old process and connection.
   - `camera_frame`, `status`, `wait`, `running`, `close`, context manager: today's `Viewer` methods, on the current process; before any launch, `ViewerClosed` for calls, `wait()` → `True`, `running` → `False`.
   - `_viewer_command(config_json)` stays the seam the tests swap.
3. **`viewer_process.py`**: `main` builds `NaoViewerConfig.from_dict(json.loads(argv[0]))` (a `ConfigError` → `NAO_VIEWER_ERROR`), then reads `mode`, `naoqi.url`, `naoqi.rate_hz`, `world.scene`, `world.variant`, `ghost`, `launch_timeout_s` from it. A scene path that doesn't exist is a `NAO_VIEWER_ERROR` naming it.
4. **`__init__.py`**: export `NaoViewer`, `NaoViewerConfig`, `NaoqiSettings`, `WorldSettings`, `ConfigError`, `CameraFrame`, `ViewerStatus`, `LaunchError`, `ViewerClosed`, `ModeError`.
5. **Examples**: `mirror.json` (mirror, `tcp://<robot-ip>:9559` placeholder URL, ghost on) and `sim-table.json` (sim, local NAOqi, `table` scene). A test loads every file in `examples/configs/`, so they can't drift from the spec.
6. **Tests and docs**: move the client, fake viewer process and live tests to `NaoViewer`; project map; statuses.

## Verification

- `tests/test_config.py`: defaults (`NaoViewerConfig()` and `from_dict({})` equal, URL `tcp://127.0.0.1:9559`, mode mirror, scene empty); partial blocks keep the other defaults; `to_dict` → `from_dict` round trip; each type and range error names its key path (`naoqi.rate_hz`, `world.variant`, `launch_timeout_s`, …), booleans rejected as numbers, non-finite numbers rejected; unknown keys at the top level and in a block; unknown bundled scene lists the bundled ones; a relative scene path in a file resolves against the file's directory; invalid JSON and unreadable files name the file; direct construction validates; every example file loads; importing `nao_viewer.config` loads neither `mujoco` nor `qi`.
- `tests/test_client.py` (fake viewer process, which now reads the config format): everything it covers today, through `NaoViewer`; plus: the config reaches the viewer process intact; the constructor starts nothing; calls before `launch()` raise `ViewerClosed`; `launch()` twice raises `RuntimeError`; `launch()` again after the window closed opens a new viewer; the context manager launches and closes.
- `tests/test_viewer_process.py`: a `ConfigError` or a missing scene path in the process's argument gives `NAO_VIEWER_ERROR` and exit code 1.
- `tests-e2e/test_viewer_live.py` through `NaoViewer`, run once against a mock NAOqi in a separate process.
