# CI: cache nao-sim's images, not Aldebaran's files

**Status:** Done

Implements [specs/ci.md](../specs/ci.md) ("The live job"): the live job caches the two images nao-sim builds (NAOqi 2.1 and `tts`) instead of the vendor files they are built from. Aldebaran's files are then only fetched to build the images, as on a user's machine, which matches nao-sim's `fetch-and-build-images`. It leaves the other two jobs unchanged.

## Scope

- `.github/workflows/ci.yml`: the vendor restore/save steps become an image restore, a `docker load` on a hit, `fetch-and-build-images` plus `docker save` on a miss, and an image save right after the build
- `specs/ci.md`, `specs/_index.md`, this plan, `plans/_index.md`: statuses

## Steps

1. The cache restore names `$RUNNER_TEMP/nao-sim-images.tar` under the key `nao-sim-images-2.1-<NAO_SIM_REF>`.
2. On a hit: `docker load -i` that file.
3. On a miss: `nao-sim fetch-and-build-images 2.1`, then `docker save -o` the file with `nao-sim/naoqi:2.1.4.13` and `nao-sim/tts:dev`, then the cache save with the restore step's primary key.
4. Compose starts the images with `--no-build` either way.
5. No extra compression: the images compress no further (1.64 GB through zstd -3, measured locally), and `actions/cache` compresses its archives itself.
