# NAO model

**Status:** Done

Implements [specs/model.md](../specs/model.md): the vendored URDF, the committed `nao.xml` with placeholder visuals, the `empty` scene, and `model.py` (`JOINT_NAMES`, `resolve_variant`, `load_world`, `NaoPose`, `PoseWriter`). It leaves out loading Aldebaran's meshes: `meshes.py` doesn't exist yet, so `resolve_variant` treats the meshes as never installed (`"auto"` gives `"placeholder"`, `"aldebaran"` raises the `fetch-meshes` error), which is the spec's behavior without meshes. The [meshes](../specs/meshes.md) plan wires in `meshes.installed()` and `meshes.apply_visuals()`.

## Steps

1. **Vendor the URDF.** Download `nao_description/urdf/naoV50_generated_urdf/nao.urdf` from `ros-naoqi/nao_robot` at `67476469a1371b00b17538eb6ea336367ece7d44`, unmodified, with the repository's `LICENSE.txt` as `LICENSE`. Write `SOURCE` (repository, commit, path) and `THIRD_PARTY_NOTICES.md`.
2. **One-off conversion** (a throwaway script in the scratchpad, not committed). MuJoCo's importer loads the URDF fine with `<compiler fusestatic="false"/>` (all frames kept, mimics imported as joint equalities), but `spec.to_xml()` output isn't readable, so the script writes the MJCF directly from the URDF's joints, origins and inertials:
   - root body `torso` with free joint `root`, folding `base_link` into it;
   - remove the massless frame bodies, turning the needed frames into sites/cameras on their parent: `imu` (accelerometer frame), the 8 FSR sites, effector sites `Head`, `LArm`/`RArm` (gripper offset, on the wrist body), `LLeg`/`RLeg` (soles), `CameraTop`/`CameraBottom` (from `Camera*_frame`, rotated so −Z looks along the link's +X and +Y is its +Z), `fovy` 47.64;
   - drop the other sensor frames (touch, sonar, infrared, bumpers, chest button), which the spec doesn't use;
   - keep `LHand`/`RHand` on the dummy gripper body with no children, and the finger joints with their imported mimic equalities, plus the `RHipYawPitch` equality;
   - add default classes `nao_joint` (position actuators: `kp`, `forcerange`, `damping` placeholders), `nao_collision` (group 3) and `nao_visual` (group 1, `contype=conaffinity=0`), and the materials `nao_white`, `nao_grey`, `nao_accent`, `nao_eye`;
   - add one `position` actuator and one `jointpos` sensor per body joint, `gyro` + `accelerometer` at `imu`, a `touch` sensor per FSR site;
   - order the torso's children Head, LArm, LLeg, RLeg, RArm so `qpos` follows NAOqi's chain order;
   - exclude contacts between bodies that are adjacent through geom-less bodies (torso–thighs, torso–upper arms, …);
   - write a readable, commented `nao.xml`. From here on `nao.xml` is the source of truth.
3. **Collision geoms**: hand-tuned capsules (limbs), boxes (torso, feet) and a sphere-capped capsule (head) in class `nao_collision`.
4. **Placeholder visuals**: author the shapes from [model.md](../specs/model.md) ("Placeholder visuals") in class `nao_visual`. Tune them by rendering offscreen images from several angles and in a few poses, and inspecting them. The head shell must leave the cameras clear.
5. **`empty.xml`**: checker floor and one directional light, no robot.
6. **`model.py`**:
   - `JOINT_NAMES`;
   - `resolve_variant` (meshes never installed, see above);
   - `load_world`: bundled name (`scenes/<name>.xml`) or path; unknown name → `ValueError` listing the bundled scenes; loads `nao.xml` as `MjSpec`, attaches its `torso` into the scene's worldbody through a frame with an empty prefix, so names stay unchanged; compiles;
   - `NaoPose.from_naoqi`: 4x4 row-major transform → position + `(w, x, y, z)` quaternion (`mju_mat2Quat`); names zipped with angles;
   - `PoseWriter`: resolves each body joint's `qpos` address and each finger joint's mimic (`multiplier`, `offset`, from the model's joint equalities) once; `apply` writes root position/quaternion, known angles, fingers from their hand value, then `mj_kinematics` and `mj_camlight` (found while rendering: `mj_kinematics` leaves `cam_xpos` at zero, so the head cameras rendered from the origin); unknown names logged once per writer.
7. **Tests** (`tests/test_model.py`), see Verification.
8. **Docs**: AGENTS.md project map (`model.py` → model.md; `third_party/` in the top-level layout), spec and plan statuses.

## Verification

`tests/test_model.py` covers, through the public API:

- **Kinematics match the URDF**: the URDF loaded by MuJoCo (base fixed) and `nao.xml` posed with the same random configurations (seeded) give the same frames, relative to the torso, for every body joint's child body, the cameras' parent frames, the effector sites (against `Head`, `l_gripper` at `LHand=0`, `l_sole`, …) and the FSR sites, within 1e-5 (nao.xml writes 6 significant digits). Joint names, order (`JOINT_NAMES`), axes and ranges match the URDF.
- **Opening the hand doesn't move the arm effector**: `LHand` 0 → 1 leaves `LArm` unchanged.
- **`PoseWriter`**: torso pose lands in `qpos[0:7]`; angles land on the named joints; fingers follow `LHand`/`RHand` with the URDF multipliers; unknown names are ignored and logged once; joints missing from the pose keep their value; out-of-range values are written as given.
- **`NaoPose.from_naoqi`**: a known rotation and translation round-trip to the expected quaternion and position.
- **`load_world`**: the default scene has the floor and all 26 joints with their names; a user scene file by path works; an unknown scene name and `variant="aldebaran"` raise errors naming the bundled scenes and `nao-viewer fetch-meshes`; `"auto"` resolves to `"placeholder"`.
- **Geom setup**: every `nao_visual` geom is in group 1 and doesn't collide; collision geoms are in group 3; rays cast across each head camera's field of view (`mj_ray`, visual group) don't hit the robot's own head.
