# Viewer API and viewer process

**Status:** Done

Implements [specs/api.md](../specs/api.md): `nao_viewer.launch` and the `Viewer` handle (`client.py`), the viewer process (`viewer_process.py`), the loopback protocol (`protocol.py`), and the `table` scene; plus the `stop` event and the sample passed to `on_frame` in [specs/viewer.md](../specs/viewer.md), and the live test of the window. It leaves out the `view` command ([specs/cli.md](../specs/cli.md)).

## Scope

- `src/nao_viewer/protocol.py` — message framing, shared by both sides
- `src/nao_viewer/client.py` — `launch`, `Viewer`, `CameraFrame`, `ViewerStatus`, `LaunchError`, `ViewerClosed`, `ModeError`
- `src/nao_viewer/__init__.py` — exports the public names only
- `src/nao_viewer/viewer_process.py` — `python -m nao_viewer.viewer_process <JSON config>`: world, source, request server, window
- `src/nao_viewer/viewer.py` — `run(..., stop=None)`, `on_frame(model, data, sample)`
- `src/nao_viewer/scenes/table.xml` — a table with objects in front of the robot
- `tests/test_protocol.py`, `tests/test_client.py`, `tests/fake_viewer_process.py`, `tests/test_viewer_process.py` — fast tier
- `tests-e2e/test_viewer_live.py` — the real window against `NAOQI_URL`
- `AGENTS.md`, specs and plan statuses

## Steps

1. **`protocol.py`**: `encode(header, payload=b"") -> bytes`; `read_message(sock) -> (header, payload)` reading exact lengths (raises `EOFError` on a clean close); `write_message(sock, header, payload)`; `PROTOCOL = 1`; ready/error line prefixes.
2. **`viewer.py`**: `run` gains `stop: threading.Event | None` (the loop also ends when it is set, closing the window) and passes the posed sample to `on_frame`.
3. **`viewer_process.py`**:
   - parse the config (url, mode, scene, variant, ghost, rate_hz, timeout); log to stderr as `LEVEL name: message`;
   - `load_world(scene or the mode's default, variant, name="nao-viewer · <mode> · <url>")`, errors → `NAO_VIEWER_ERROR` + exit 1;
   - bind `127.0.0.1:0`; `NaoqiSource(url, rate_hz, commanded=ghost)`;
   - `RequestServer`: an accept thread (one connection, waits up to `timeout` after the ready line) and a reader thread queueing requests; `on_frame` prints the ready line on the first frame, then answers queued requests (`hello`, `status`, `camera_frame`, `stop`, unknown → `ok: false`); EOF or `stop` sets the stop event;
   - camera renders: one `mujoco.Renderer` per `(width, height)`, created on first use after raising `model.vis.global_.offwidth/offheight` if needed; `update_scene(data, camera)`, `render()` → RGB bytes.
4. **`client.py`**:
   - `_viewer_command(config)`: `mjpython` next to `sys.executable` on macOS (missing → `LaunchError`), `sys.executable` elsewhere; tests replace it to run the fake viewer process;
   - `launch`: start the subprocess; a stdout thread hands the first line over and then drains; a stderr thread relays lines to the `nao_viewer.viewer_process` logger at their level (`DEBUG` without one) and keeps the last 50; wait for the ready line up to `timeout`, connect, `hello` (protocol check);
   - `Viewer`: requests serialized by a lock; a closed socket or exited process → `ViewerClosed`; `camera_frame` validates the camera and raises `ModeError` in mirror mode before any request; `status`, `wait`, `running`, `close` (`stop`, wait 5 s, terminate, then kill), context manager.
5. **`table.xml`**: floor and light as `empty`, a table 0.35 m in front of the robot, a few colored objects on it, in view of `CameraTop` and `CameraBottom` at rest.
6. **`__init__.py`**: re-export the client's public names only.

## Found while building

- **libqi writes its own log lines to stdout** (`[W] … qi.path.sdklayout …`), so the ready line isn't always the first one: `launch` picks out the first `NAO_VIEWER_READY`/`NAO_VIEWER_ERROR` line and relays the rest at `DEBUG`. api.md says so.
- **The top camera looks almost level**: with the table 20 cm away it saw only the floor. The table now spans 30–70 cm, so both cameras see objects on it.
- **Scenes use degrees** (MuJoCo's default), unlike `nao.xml`: the objects' `euler` rotations are in degrees.
- **Timings** (real viewer process, mock NAOqi, M-series Mac): `launch` ≈ 0.8 s; the first 640x480 frame ≈ 75 ms (renderer creation), then ≈ 23 ms per frame, one render-loop tick plus the render.

- `tests/test_protocol.py`: round trips with and without payload over a socket pair, including large payloads read in pieces; a clean close is `EOFError`.
- `tests/test_viewer_process.py`: the request server driven directly with a stub renderer and a fake source: queueing and answering on `on_frame`, the ready line on the first frame, `status` fields, `camera_frame` in sim (shape, `pose_seq`, `pose_age`) and refused in mirror, unknown ops answered without closing, `stop` and EOF setting the stop event; the real `Renderer` path offscreen when OpenGL is available.
- `tests/test_client.py` (fake viewer process): launch and handshake, `status`, `camera_frame`, `ModeError` without a round trip, `LaunchError` on `NAO_VIEWER_ERROR`, early exit and timeout (with stderr tail), `ViewerClosed` and `wait()` after the viewer exits, `close()` and the context manager, stderr relayed at the right levels, concurrent calls, missing `mjpython`, and importing `nao_viewer` loading neither `mujoco` nor `qi`.
- `tests-e2e/test_viewer_live.py`: real frames from `launch(NAOQI_URL, mode="sim")`, not blank, changing when the head moves (not on a real robot). Run once by hand against a mock NAOqi served from a separate process.
